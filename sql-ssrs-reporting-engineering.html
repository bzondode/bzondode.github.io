SQL & SSRS Reporting Engineering

A portfolio-safe reporting-engineering case study focused on grain control, SQL Server performance tuning, validation, parameterization, and SSRS-ready delivery.

THE REPORTING PROBLEM

One person could appear many times before the report even reached SSRS.

The source model contained several legitimate one-to-many relationships: people could be linked to multiple cases, cases could contain multiple offenses, and people could have multiple addresses. A straightforward join therefore expanded below the required reporting grain.

Person×Case×Offense×Address

1,971 Distinct qualifying people
3,369 Rows beyond person grain

PERFORMANCE ENGINEERING

The first correct design still performed too much repeated work.

After grain was corrected, benchmarking exposed expensive repeated aggregation. The redesigned version materialized reusable working sets and indexed them around the repeated lookup key, PersonID. Targeted source-table indexes were then added only where the access pattern justified them.

EARLIER DESIGN

Correct output, expensive reuse

Repeated XML/string aggregation revisited underlying joined logic many times.

ENGINEERED DESIGN

Materialized, indexed working sets

Person-case and person-offense grains were stored once and reused predictably.

SSRS DELIVERY

The reporting layer stays thin because the dataset is already report-ready.

The final SQL dataset remains one row per person and is parameterized for start date, end date, and offense group. SSRS handles profile-card presentation, pagination, headers, footers, and print/PDF delivery rather than repairing relational duplication.

TECHNICAL HIGHLIGHTS

The project connects reporting logic to SQL Server engine behavior.

GRAIN

Explicit working-set grain

Each intermediate table has a known level of detail before final assembly.

MATERIALIZATION

Reusable temp-table structures

Repeated access is redirected to smaller, purpose-built working sets.

INDEX DESIGN

Access-pattern-driven keys

Key order and included columns follow filtering, joins, ranking, and output needs.

MEASUREMENT

Logical reads over anecdotes

Repeatable page-access measurements provide stronger evidence than isolated elapsed times.

VALIDATION

Independent reconciliation

Performance changes are checked against source populations and business rules.

REPORTING

Thin SSRS presentation layer
