Automated Analytics ETL & Data Quality Pipeline

A reproducible Python analytics-engineering workflow that transforms messy operational-style source data into validated, BI-ready analytical fact tables.

TOOLSPython · Pandas · SQLite

This public case study is based on real ETL work completed previously, recreated with synthetic data so the engineering approach can be demonstrated safely.

THE PROBLEM

Operational data is rarely analysis-ready.

The source included multi-value offense text, inconsistent delimiters and casing, blank analyst fields, wide Boolean flags, free-text narratives, missing geography, non-standard identifiers, and records requiring explicit analyst intervention.

Multi-value fields

Multiple offenses could exist inside a single incident-level text field.

Unstructured signals

Narratives contained useful analytical clues not available as structured columns.

Quality exceptions

Some records required explicit overrides instead of hidden hard-coded corrections.

OFFENSE NORMALIZATION

One incident can legitimately become multiple offense rows.

Analyst-curated offense values are preferred when valid, source offense text is used as fallback, mixed delimiters are normalized, labels are mapped to controlled categories, provenance is recorded, and source-versus-analyst mismatches are surfaced.

233Source/analyst mismatches

EXPLICIT QUALITY OVERRIDES

Manual corrections are treated as data, not invisible code.

Records unresolved by normal logic were handled through a separate override table. Each override had to reference a valid incident, use a canonical offense value, and preserve the final CaseNo × OffenseType grain.

205Overrides accepted

NARRATIVE ENRICHMENT

Free text becomes structured analytical features.

Deterministic rule-based matching converts selected narrative clues into structured fields while preserving the original narrative.

Derived fields

ForcedEntryFlag, NoForceFlag, SmashAndGrabFlag, UnknownEntryMethodFlag, MethodOfEntry, and NarrativeRuleConflict.

Observed enrichment

351 smash-and-grab, 338 forced-entry, 374 no-force, 379 unknown, and 0 rule conflicts.

OUTCOME

A reproducible, auditable, grain-aware analytical pipeline.

The project demonstrates that ETL quality is not just about moving data between files. It is about controlling how meaning, grain, exceptions, validation, and trust move through the pipeline.

Automation should make a process more reliable, not merely faster.
